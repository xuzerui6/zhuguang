# 产品评审指南

给第一次评审逐光的家长、学员、教练和技术同事。先记录设备、客户端版本和城市，再尝试完成下面的任务。

| 角色 | 建议任务 | 观察点 |
| --- | --- | --- |
| 家长与学员 | 在[官网](https://beijingzhuguang.top/)切换北京/长春，查找教练，阅读资料和价格 | 城市和项目是否同步；价格、教练资质和空状态是否清楚 |
| 学员（测试账号） | 建立档案，发起预约，查看教练反提案，打开消息与训练记录 | 返回页面后草稿是否保留；时间、地点和确认状态是否一致 |
| 教练（测试账号） | 查看待确认预约，提出新时间或地点，填写训练记录 | 能否判断下一步；重复操作和失败是否有明确反馈 |
| 技术评审 | 检查服务端授权、预约状态、数据迁移、端侧恢复和版本发布 | 是否有跨账号访问、错误终态、重复写入或未配置能力误开放 |

官网可匿名查看。测试预约、教练入驻审核、消息、收款等写操作请在维护者提供的隔离环境执行。Android 记录实际版本号；小程序请向维护者索取当前可用的体验入口。请勿使用别人的运营账号。

## 提交反馈

在[私有仓库 Issues](https://github.com/xuzerui6/zhuguang/issues/new/choose)选择「产品评审反馈」，每个问题单独提交。记录页面、版本、身份与城市、复现步骤、实际与预期结果。截图请先遮盖姓名、联系方式、验证码、地址和消息正文。涉及漏洞或私密数据时，先私下联系维护者，不附原始数据。

优先处理无法完成任务、数据不一致或越权问题；再处理理解成本、交互和视觉细节。没有足够信息时可标为待复现，不把猜测写成已证实的问题。
