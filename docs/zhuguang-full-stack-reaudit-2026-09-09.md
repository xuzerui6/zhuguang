## 一、审计结论

**需要整改，但不需要推翻视觉重做。** 官网和工作区已有可延续的绿色品牌、运动图片、信息结构与主次操作。当前主要问题是业务状态和操作入口不够可靠，以及不同页面的控件与交互细节不一致，而不是缺少一套新视觉。

本轮最高优先级为 **P1：运营工作队列隐藏未分类新咨询，且缺少就地核验入口，容易漏处理业务**。其余确认问题包括失效预约进入“最近安排”、登录恢复成功仍闪现失败提示、收藏删除同步缺陷、发布表单裁切、后台菜单可访问性不足，以及小屏页脚隐藏服务说明链接。

与上次报告相比，以下改进已在当前代码、已有测试或线上页面中得到支持，不能继续照抄为旧的发布阻塞：

- 版本中心已改为先上传安装包、再凭回执创建清单，当前新版本 code 默认显示 26；确认对话框能够取消并返回焦点。生产上传、创建和发布未实际提交。

## 五、Codex 实施任务

### P1-1：让未分类新咨询进入可处理工作队列

**问题与影响**：新线索默认未分类，匹配中心默认 `production_eligible`。用户刚提交的咨询可能不会被运营看到。现有分类表单放在“交易与指标”，还要求手工填写完整实体 ID，服务线索行没有提供直接核验入口。业务处理状态和指标资格是两个维度，不应互相替代。

**证据与位置**：S04、S11；[运营页面](/C:/Users/16013/Desktop/教练平台/app/_components/ops-pages.tsx:95)、[线索默认视图](/C:/Users/16013/Desktop/教练平台/app/_components/ops-pages.tsx:180)、[线索查询](/C:/Users/16013/Desktop/教练平台/server/api/operations.ts:109)、[分类规则](/C:/Users/16013/Desktop/教练平台/server/api/data-classification.ts:8)。

**Codex 要做**：

- 为运营线索列表增加明确的工作队列视图，包含 `production_eligible` 与 `unclassified`，默认排除 QA 和已排除数据，保留现有类型、状态和搜索能力。
- 列表展示中文分类标签；增加行内“核验分类”，自动携带真实实体 ID，不让运营人员从开发工具抄 ID。
- 概览中的未分类线索数量能够直接进入相应列表；空态区分“当前筛选无记录”和“平台没有记录”。
- 分类原因必填，沿用现有最高权限校验、原子更新与审计记录；遇到并发冲突刷新后再处理，不能假显示成功。
- 指标默认仍只计真实合格。标记已联系、确认需求或新建线索都不得自动改变指标资格。

**验收**：本地测试新增咨询后，工作队列可见而真实合格指标不增加；标为 QA 后退出默认工作队列；核验为真实合格后进入对应指标；审计失败回滚、并发冲突和无权限操作均有测试。不得使用生产记录验证写入。

### P2-2：登录成功不得闪现恢复失败

- **问题**：恢复请求返回后无条件设置失败状态，随后才在成功时刷新页面。此前观察到失败提示后页面自行恢复，不应误记为人工重载才成功。
- **位置**：[登录恢复组件](/C:/Users/16013/Desktop/教练平台/app/_components/access-denied.tsx:24)。
- **Codex 要做**：明确恢复中、成功、失败状态；成功到新页面完成期间继续显示恢复中或成功，不显示失败；错误分支展示可重试状态。保持现有一次刷新策略与上游故障时保留会话的边界。
- **验收**：成功但页面刷新较慢、刷新失败、服务不可用及组件卸载均有覆盖；成功路径不出现“未能恢复页面”。

### P2-3：修复收藏删除和离线同步

- **问题**：刷新时把本地与远端收藏不断求并集，远端删除无法从本地移除；收藏写入失败被忽略。对当前合并函数输入本地 `[7]`、远端 `[]`，仍得到 `[7]`。
- **位置**：[Bootstrap 合并](/C:/Users/16013/Desktop/教练平台/app/mobile/app.tsx:193)、[收藏操作](/C:/Users/16013/Desktop/教练平台/app/mobile/app.tsx:335)、[合并函数](/C:/Users/16013/Desktop/教练平台/app/mobile/domain.ts:103)。
- **Codex 要做**：已登录状态使用服务端快照叠加本账号尚未同步的增删操作；取消收藏必须保留删除意图。按账号隔离本地状态与待同步操作，旧请求不得覆盖新账号或较新的操作。失败不得静默当成功；离线或失败时提供待同步状态与重试能力。
- **兼容要求**：保留访客本地收藏；如保留首次登录合并，只在该边界执行一次，不能在每次轮询时无限求并集。
