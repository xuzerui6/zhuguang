# 逐光官网转化、信任与平台成熟度审计

- 审计日期：2026-09-02
- 审计对象：https://www.beijingzhuguang.top/
- 产品阶段：北京经营、按全国领先级产品体验持续建设
- 审计范围：公开官网首页、移动导航、教练目录、教练详情、训练咨询、教练合作、登录、服务保障、隐私说明和页脚
- 执行说明：Codex 应先阅读本文件，再实施“P0 必须完成”和“P1 建议本轮完成”，并可按 P2 扩展产品能力、页面、接口、数据结构、工作台和客户端。唯一不可扩大的经营边界是服务城市：本项目继续只经营北京。

## 一、总体结论

当前官网已经达到成熟北京试点平台的公开获客水平：首屏定位清晰、价格和地点规则真实、教练资料没有虚构、咨询与预约边界明确，移动导航和基础响应式表现稳定。

当前可以按“全国领先级产品体验”建设，但不适合宣传“全国领先体育培训平台”或全国覆盖。线上仅展示 3 位通州区田径教练，缺少真实课程规模和学员评价，仍采用线下支付，且生产页脚没有公开经营主体、客服、投诉和备案信息。视觉完成度已经较高，主要差距位于真实供给规模、公开责任主体和交易保障。

产品目标统一为“北京经营，全国领先级体验”。建议继续使用“北京试点”“北京专业体育教练”“先核验，再预约”等真实表述。不得新增“全国领先”“全国覆盖”“海量教练”等未经事实支持的公开文案。

## 二、项目扩张授权与硬边界

### 可以扩大

Codex 可以根据现有架构和风险拆分扩展以下范围：

- 新增或重构公开页面、学员流程、教练流程和运营工作台。
- 增加 D1 表、字段、索引、审计记录和向后兼容迁移。
- 扩展北京范围内的运动项目、服务区域、教练供给和训练方案。
- 完善咨询、预约、改期、取消、履约、售后、投诉和评价闭环。
- 在真实商户资料和交易规则具备后接入在线支付、退款、对账和平台服务费能力。
- 扩展 Android、Web、通知、消息、运营分析和跨端一致性。
- 增加真实数据驱动的信任指标、运营看板和风险控制。
- 为未来能力增加服务端配置和功能开关，未满足真实条件时保持关闭。

### 不可扩大

- 经营城市必须保持北京，不增加北京以外城市，不提供全国城市切换。
- 所有区域数据、咨询、预约、场馆和教练服务范围必须继续校验为北京。
- 不得宣传全国覆盖、全国第一或全国领先等无法证明的排名或覆盖范围。
- 不得虚构教练、评价、课程、成交额、经营主体、备案、保险、场馆或合作机构。
- 未取得真实商户账号、支付参数、退款规则和平台收费规则时，不启用真实在线收款。
- 未取得真实保险或合作合同前，不展示保险保障或合作背书。

### 扩张原则

- 先保持现有流程可用，再通过增量迁移和功能开关扩展。
- 涉及支付、收费、退款、保险和对外承诺时，Codex 可以完成架构和测试环境能力，但必须把缺失的真实商业配置列为上线阻塞。
- 可以修改 Android、预约契约和工作台权限，但必须同步更新接口契约、数据库迁移、权限测试和回滚说明。
- 每个扩展工作流必须包含空状态、错误状态、权限校验、审计记录和移动端体验。

## 四、Codex 实施任务

### P0 必须完成：公开责任主体与匿名隐私联系渠道

1. 保留页脚现有“有值才显示”机制。
2. 检查并支持以下服务端配置：
   - `SITE_OPERATOR_NAME`
   - `SITE_SUPPORT_EMAIL`
   - `SITE_SUPPORT_PHONE`
   - `SITE_COMPLAINT_CONTACT`
   - `SITE_ICP_NUMBER`
   - 公安备案编号和链接配置
3. 空值必须隐藏整项，不得展示“待补充”、示例号码、虚构主体或虚构备案号。
4. 生产环境只有在用户提供真实值后才配置和公开。
5. 隐私政策必须提供匿名咨询用户也能使用的联系渠道，例如真实客服邮箱、客服电话或公开隐私请求表单。
6. 如果没有真实联系渠道，保持隐藏，并在交付报告中将该项标记为阻塞，不得自行编造。

验收标准：

- 无配置时，页脚不出现空标签或占位内容。
- 有配置时，主体、客服、投诉和备案信息正确显示，链接可访问。
- 未登录用户可以找到并使用真实的隐私问题联系渠道。
- 页脚在 `390x844` 下无横向溢出。

### P1-1：让移动首屏看到训练目标入口

目标：在 `390x844`、页面缩放 100%、正常中文字体加载完成的条件下，训练目标控件至少部分进入首屏且可识别。

允许的方式：

- 适度压缩首屏上下间距和按钮间距。
- 缩短不影响承诺边界的说明文案。
- 将筛选区移动端布局调整为更紧凑、稳定的结构。

禁止：

- 隐藏地点、价格或“教练确认后生效”等关键信息。
- 通过过小字体、负间距或文本重叠换取露出。
- 让桌面端筛选布局退化。

验收标准：

- `390x844` 下训练目标入口可见。
- 标题、说明、两个 CTA 和信任标签不重叠。
- 页面无横向滚动。

### P1-2：补齐移动教练卡的显性转化操作

1. 移动端每张教练卡显示“查看档案”和“咨询这位教练”两个明确操作。
2. “查看档案”进入 `/coaches/{id}`。
3. “咨询这位教练”进入 `/?coach={id}#service-inquiry`。
4. 保留卡片现有核验状态、适合人群、服务区域、时间规则和价格。
5. 不新增未经审核的教学风格、可约时间、评价或训练照片。

验收标准：

- 两个操作均有至少 44px 的触控高度。
- 键盘可以聚焦并识别操作名称。
- 教练参数在咨询表单中正确显示。
- 桌面端详情侧栏和现有收藏功能不回归。

### P1-3：降低移动咨询表单的视觉长度

1. 姓名、手机号/微信、训练区域、运动项目和训练需求保持主要流程。
2. 邮箱、年龄段或年级、期望时间继续保留为选填。
3. 可以把选填字段放入默认收起的“补充更多信息”区域。
4. 教练定向咨询时继续隐藏已由教练资料确定的运动项目字段。
5. 不改变后端字段、加密存储、Turnstile、限流和线索分类逻辑。

验收标准：

- 手机号或微信至少填写一项的服务端校验保持有效。
- 展开和收起不清空已经填写的数据。
- 错误信息与字段关联，并能被辅助技术读取。
- 提交成功后不泄露联系方式，不自动创建预约。

### P1-4：消除桌面公共导航的身份入口歧义

当前桌面端同时出现“登录”和“进入平台”，两者目的接近。

建议：

- 将主要入口明确为“学员登录”或“学员入口”，指向 `/login?next=/student`。
- 认证教练继续通过统一登录后按权限切换工作台。
- 运营入口继续只放在页脚，不在主导航高亮。
- 避免同时保留两个含义接近的登录操作。

验收标准：

- 首次访问者可以判断哪个入口用于学员预约。
- 教练和运营权限仍由服务端决定，不通过前端文案推断权限。
- 桌面和移动导航命名一致。

### P2 授权扩展能力：北京经营范围内可以实施

P2 不再是禁止项。Codex 可以在完成 P0 和 P1、保证现有流程不回归后，按以下顺序扩展。

#### P2-1：北京供给与运营闭环

- 支持北京 16 个区、更多真实运动项目、更多审核教练和场馆。
- 完善教练合作线索、资料核验、审核版本、发布和下线流程。
- 建立服务区域、接单状态、价格版本和核验更新时间的真实数据来源。
- 运营工作台增加搜索、分类、分派、处理时限、审计和导出权限控制。

#### P2-2：预约、履约和售后闭环

- 完善试课、常规课、改期、取消、教练反提案、完成确认和训练记录。
- 增加售后工单、投诉、证据材料、处理状态和双方通知。
- 真实完成课程后才允许评价；评价审核、匿名展示和申诉过程可追踪。
- 价格、取消规则和服务地点在提交时生成不可变快照。

#### P2-3：在线交易能力

- 可以设计和实现支付、退款、对账、平台服务费和交易审计。
- 支付提供方、商户主体、收费比例、退款规则和发票责任必须使用真实配置。
- 缺少真实商户资料时只能运行测试或沙箱模式，生产入口保持隐藏。
- 不得把尚未开通的托管或赔付能力写进公开服务承诺。

#### P2-4：跨端与通知

- 可以同步调整 Android、Web、消息、通知和账号工作台。
- 同一预约、线索、工单和权限状态必须跨端一致。
- 锁屏通知继续避免展示未成年人姓名和敏感训练信息。
- 新增分析事件时不得记录手机号、微信号、邮箱、健康信息或私人消息正文。

#### P2-5：真实信任指标

真实业务数据形成后，可以增加：已核验教练数、真实完成课程数、真实评价数、北京实际服务区、核验更新时间和真实售后处理状态。指标必须直接来自业务数据库，并在无数据时隐藏整项。

1. P0 和全部 P1 验收标准通过；已实施的 P2 工作流也有对应测试和验收记录。
