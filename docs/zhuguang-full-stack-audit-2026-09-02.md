## 一、总体结论

当前官网已经达到成熟北京试点平台的公开获客水平：首屏定位清晰，价格、训练地点和教练确认规则真实，移动菜单与筛选路径稳定，教练资料没有通过虚构评价或课量制造规模感。学员端与教练端的主要页面已经形成统一产品形态，Android 真机未发现原生崩溃。

当前版本仍需完成核心流程修复和回归。主要问题不是首页视觉，而是 Web 会话 15 分钟后无法续期、Android 已结束预约展示错误、课程完成确认存在并发一致性风险，以及公开信任指标分类没有完整参与统计。

产品目标继续统一为“北京经营，全国领先级体验”。公开文案可以使用“北京专业体育教练”“先核验，再预约”“北京试点服务”等真实表述，不得新增“全国领先”“全国覆盖”“海量教练”等未经事实支持的宣传。

## 四、Codex 实施任务

### P1-1：实现安全的 Web 会话续期

1. 建立由服务端持有的 Web 刷新流程，读取 HttpOnly `WEB_REFRESH_COOKIE` 并调用上游 `/api/v1/auth/refresh`。
2. 刷新成功后轮换访问令牌与刷新令牌，重新设置 `Secure + HttpOnly + SameSite=Strict` Cookie。
3. 刷新失败、设备不匹配、令牌复用或上游拒绝时清理会话 Cookie，并返回明确登录状态。
4. 服务器直接导航和浏览器刷新也必须能够续期，不能只依赖客户端请求拦截器。
5. 处理多个页面请求同时刷新时的竞争，同一刷新令牌只能成功使用一次。
6. 刷新后继续使用服务端角色、资源所有权和主运营账号规则，不得扩大权限。
7. 增加过期访问令牌、有效刷新、无效刷新、并发刷新和退出登录测试。

验收标准：

- 访问令牌过期后直接打开 `/student`、`/coach-workspace` 或 `/ops`，无需重新输入验证码。
- 刷新令牌无效时才进入登录页，旧 Cookie 被清理。
- 浏览器 JavaScript 无法读取访问令牌和刷新令牌。
- 运营账号连续使用超过 30 分钟后仍可正常跳转受保护页面。

### P1-2：修复 Android 预约全部终态

1. 提取统一预约展示模型，根据 `booking.status`、`paymentStatus` 和 `completion.status` 计算状态标签、支付文案、时间线和可用操作。
2. 明确覆盖 `pending_coach`、`confirmed`、`completed`、`cancelled`、`rejected`、`expired` 等全部现有状态。
3. 支付文案必须读取真实 `paymentStatus`，不得把所有非待确认状态写成“线下待支付”。
4. 已完成预约显示完成节点，并保留真实可用的评价和联系操作。
5. 已取消、拒绝和失效预约不得继续显示教练确认、支付或完成操作。
6. 删除没有真实运营保障的“24 小时内处理”，改为不承诺固定时效的事实性文案。
7. 无效或缺失时间使用安全回退，不显示“提交于 已提交”。
8. 增加全部预约状态、支付状态和完成确认状态的单元及渲染测试。

验收标准：

- “已完成”卡片不再出现“待教练确认”或“确认后联系”。
- 取消、拒绝、失效和完成状态各自具有正确且不冲突的时间线。
- 用户只能看到当前状态允许执行的操作。
- `390x844` 下文案不溢出，底部导航不遮挡最终操作。

### P1-3：为课程完成确认增加原子幂等控制

1. 为完成确认响应增加客户端和服务端幂等键。
2. 使用新增不可变响应记录或同等级机制，保证每个 `completion_request_id` 只能形成一个最终决定。
3. 使用 `0018` 之后的新增量迁移，不修改已经存在的历史迁移。
4. 将响应记录、请求状态、预约状态、事件和异议工单放在同一个原子 D1 批次或等价一致性边界。
5. 相同幂等键和相同决定重复提交时返回首次结果，冲突决定返回 409。
6. 不得仅依赖前端禁用按钮解决并发问题。
7. 增加 `accepted/accepted`、`accepted/disputed`、`disputed/disputed` 和网络重试测试。

验收标准：

- 并发重复请求只能产生一个最终决定和一条对应业务事件。
- 接受完成后不能再创建完成异议工单。
- 已提出异议后不能再把预约更新为已完成。
- 任一批次失败时不留下半完成状态。

### P1-4：修复真实指标分类与统计来源

1. 为评价和售后工单保存明确的数据分类，或使用可证明等价的最新分类事件查询。
2. 分类前验证目标实体存在，零行更新必须返回 404/422，不能记录虚假成功事件。
3. 公开评价必须同时满足：评价已审核、评价为 `production_eligible`、预约为真实合格。
4. 教练、账号、预约、评价和工单使用一致分类枚举和审计记录。
5. 若工单当前不进入公开指标，运营界面应明确分类用途，不能暗示它会改变公开数字。
6. 增加未分类、QA、排除、合格、重新分类、不存在实体和重复操作测试。
7. 修复后仍保持生产指标开关关闭，直到历史数据完成真实分类和人工复核。

验收标准：

- QA 和排除评价永远不会进入公开指标。
- 不存在的实体分类不会返回成功。
- 每个公开数字都能回溯到实体资格、审核记录、操作者、原因和时间。

### P2-1：修复 Android Lint 与最低版本兼容

1. 把 `windowLightNavigationBar` 移到 `values-v27`，API 24-26 使用兼容主题。
2. 对 `tools:node="remove"` 权限使用可审计的定向处理，确保 Lint 通过，同时验证合并 Manifest 不含位置、电话、存储和 `QUERY_ALL_PACKAGES` 权限。

### P2-2：明确客户端渠道键的安全边界
